# PRD 01: Shared Data Bridge (RN → Widget)

## Introduction/Overview

Widgets cannot run the React Native runtime. They read pre-computed data from a shared container and render it in SwiftUI. This PRD defines the **contract and plumbing** that moves the app's weather data into a place the widget can read: a versioned JSON `WidgetSnapshot` written to the App Group's shared `UserDefaults` whenever the app fetches or loads weather for the **active** city.

The bridge is the single most important integration point in the suite — every widget reads from it. It must be a stable, versioned, typed contract on both sides (TypeScript writer, Swift reader) so the two can evolve without silently breaking.

**Scope note (active-city only):** The app holds a full `WeatherScenario` only for the **active** city. Every other city in the picker has only a `CityCurrent { temp, cond, label, humidity }` (the batch `fetchCitiesCurrent` result), which is too thin to build a full snapshot. Therefore this PRD writes the full snapshot for the **active city only**. Per-city snapshots for non-active cities are deferred to **PRD 06**, which resolves them via an on-demand fetch (PRD 03 US-004 becomes the *primary* data path for non-active configured cities, not an exception).

Depends on: **PRD 00** (App Group `group.com.myweatherai.app` must exist; `aiweather` scheme registered; widget bundle id `com.myweatherai.app.widgets`; suite-wide iOS deployment-target floor **16.4**).

## Goals

- Define a versioned `WidgetSnapshot` JSON schema that mirrors the app's `WeatherScenario` but is trimmed to what widgets actually render.
- Write the **active city's** full snapshot to shared `UserDefaults(suiteName: "group.com.myweatherai.app")` every time the app obtains weather for that city (live fetch or stale-cache fallback), under both the active-pointer key and the per-id key.
- Persist the temperature unit (currently ephemeral in-app state) and mirror it into the shared container so app-push snapshots and the widget's independent fetch (PRD 03) agree on °C/°F.
- Maintain a `wxai.widget.index` of `{ id, name, lat, lon }` entries so PRD 06's on-demand fetch knows each city's coordinates.
- Provide a typed TypeScript writer module and a matching Swift `Codable` decoder.
- Reload widget timelines after each write so widgets reflect fresh app data promptly (best-effort; WidgetKit budgets reloads).
- Degrade gracefully: stale data, missing fields, and "no data yet" all decode sensibly (rendered in later PRDs, but the schema must support them).

## User Stories

### US-000 (prerequisite): Persist the temperature unit and mirror it to the App Group
**Description:** As a user, I want my °C/°F choice to survive an app relaunch AND show correctly in the widget.

**Context:** `unit` is currently ephemeral `useState<'C'|'F'>('C')` at **App.tsx:83** — it resets to °C on every cold launch. This is a pre-existing in-app bug and a hard blocker for any widget unit story: without persistence the widget unit is non-deterministic.

**Acceptance Criteria:**
- [ ] Migrate App.tsx:83 from `useState` to `useStorage<'C' | 'F'>('wxai.unit', 'C')` (the project's existing AsyncStorage-backed hook), so the in-app unit persists across relaunch.
- [ ] On every unit change, mirror the value into shared `UserDefaults` under the stable key `wxai.widget.unit` (a bare string `"C"` or `"F"`, not JSON), so BOTH the app-push snapshot AND the widget's independent fallback fetch (PRD 03 US-004) read the same unit.
- [ ] The mirror write is hooked into the `onUnitChange` handler currently wired as `setUnit` at **App.tsx:313** (rename to a small `handleUnitChange` that calls the storage setter and the shared-defaults mirror). It must NOT depend on a weather commit firing.
- [ ] Toggling the unit also rewrites the active snapshot's `unit` field (so the widget flips °C/°F without waiting for the next fetch) and requests a debounced reload.
- [ ] Typecheck passes; relaunching the app in the iOS Simulator preserves a previously-selected °F.

### US-001: Build and wire the custom `ExpoSharedDefaults` native module (default bridge)
**Description:** As a developer, I want to write to the App Group's shared `UserDefaults` from JavaScript AND trigger a WidgetKit reload.

**Context:** This native module is **mandatory, not a contingency**. `react-native-userdefaults` exposes only get/set/remove/getAll — it has **no** `WidgetCenter.reloadAllTimelines()`, so it cannot satisfy US-004 on its own. We author a small (~40-line) local Expo module instead. Because `ios/` is gitignored and regenerated by prebuild, the module MUST be authored as a local Expo module / config-plugin that survives `expo prebuild`.

**Acceptance Criteria:**
- [ ] A local Expo module `ExpoSharedDefaults` is created (Swift) exposing exactly: `setString(key, value)` → `UserDefaults(suiteName: "group.com.myweatherai.app")?.set(value, forKey: key)`; `getString(key) -> String?` → `.string(forKey:)`; `removeKey(key)` → `.removeObject(forKey:)`; and `reloadWidgets()` → `WidgetCenter.shared.reloadAllTimelines()`.
- [ ] A JS helper module wraps these with the suite hardcoded; values are JSON strings (one string per key — see Design Considerations).
- [ ] The module is registered so `npx expo prebuild -p ios --clean` regenerates `ios/` with the module linked and the app still compiles (the module is NOT a hand-edit inside `ios/`).
- [ ] Smoke test: write a key from JS, read it back in a Swift unit test / Xcode preview / the placeholder widget; the value matches. This write→read-back across the suite is the proof of the shared container, not gallery appearance.
- [ ] `expo prebuild` and a clean Xcode build both succeed; Typecheck passes.

### US-002: Define the `WidgetSnapshot` schema (shared contract)
**Description:** As a developer, I want one authoritative schema both sides agree on.

**Acceptance Criteria:**
- [ ] New file `src/widgets/snapshot.ts` exports the `WidgetSnapshot` TypeScript type and a `buildSnapshot(wx, city, unit)` pure function mapping `WeatherScenario` (+ `City`) → `WidgetSnapshot`.
- [ ] Schema includes `schemaVersion: 1`, `generatedAt` (epoch ms), and `tzOffsetMinutes` (see field mapping below).
- [ ] All temperatures stored in **°C** (integers); `unit` ('C'|'F') carried so the widget converts at render.
- [ ] `cond` uses the exact 8-value `Condition` union from `src/data/weatherData.ts`.
- [ ] `city` carries `lat`/`lon` read from the `City` object (NOT parsed from the id string — see my-location note below).
- [ ] `buildSnapshot` is covered by a fixture test (see AC-5 in Success Metrics) proving every field maps; the fixture asserts `current.hi >= current.lo` and, for each `days` entry, `hi >= lo`, to catch a lo/hi swap.

**Field mapping (pin these precisely — source = `WeatherScenario` from `src/data/weatherApi.ts`):**

- **`days[]` from `DayTuple`** — source `wx.days` is `DayTuple = [label, cond, LO, HI, pop]` (see `weatherData.ts:22`). LO is at **index 2**, HI at **index 3**. Map: `label = d[0]`, `cond = d[1]`, `lo = d[2]`, `hi = d[3]`, `pop = d[4]`. (lo BEFORE hi — do not assume hi-then-lo.)
- **`current.precipProb` from `wx.precip`** — use `wx.precip` (an integer **percent**, 0–100), NOT `wx.precipMm` (millimetres). These are distinct fields on `WeatherScenario` (`weatherData.ts:49–50`). The schema field is named `precipProb` and is a percent.
- **`pop` units (hourly + `days[].pop`)** — `pop` is an integer **percent 0–100** (source `precipitation_probability`), NOT a 0–1 fraction. Document this so the widget renders it directly as `%`.
- **`hourly[].ts` + `tzOffsetMinutes`** — derive a machine-readable absolute time per hour. The display `h` ("Now"/"3PM") is NOT parseable back to a `Date`, but PRD 03 needs real timestamps to stamp timeline entries. In `buildSnapshot`, parse the source ISO `hourly.time[i]` (the same value `isoToDecimalHour` consumes) into `ts: number` (epoch ms). Carry one snapshot-level `tzOffsetMinutes` derived from the source ISO's offset, so the widget can render local hour labels independent of the device timezone.
- **`sun` fields (option b)** — sunrise/sunset in `WeatherScenario` are already pre-formatted display strings (`formatTimeShort`), which are NOT re-parseable. Since we are already deriving lat/lon and tz, carry the **raw decimal hours** `srHour`/`ssHour` (`weatherApi.ts:397–398`) plus `sunPct`, so SwiftUI can format and draw an arc natively. Keep the formatted `sunrise`/`sunset` strings only as a verbatim convenience for inline text. (This is option (b) from review; do not imply render-time flexibility the formatted strings don't have.)

The schema (authoritative):

```ts
interface WidgetSnapshot {
  schemaVersion: 1;
  generatedAt: number;            // epoch ms
  tzOffsetMinutes: number;        // source-city UTC offset, derived from source ISO
  unit: 'C' | 'F';
  staleAt?: number;               // epoch ms of source cache when data is a stale fallback
  city: {
    id: string;                   // cityId(lat,lon) or 'my-location'
    name: string;
    lat: number;                  // from City.lat (NOT parsed from id)
    lon: number;                  // from City.lon
    admin1?: string;
    country?: string;
    isCurrentLocation?: boolean;
  };
  current: {
    temp: number;                 // °C, integer
    feels: number;                // °C
    hi: number;                   // °C   (assert hi >= lo)
    lo: number;                   // °C
    cond: Condition;              // 'clear'|'partly'|'cloud'|'rain'|'snow'|'fog'|'storm'|'night'
    label: string;                // e.g. 'Partly cloudy'
    isNight: boolean;
    humidity: number;             // %
    wind: number;                 // km/h
    precipProb: number;           // %  <- wx.precip (NOT precipMm)
    uv: number;
    aqi?: number;
    aqiWord?: string;
  };
  headline: { pre: string; em: string; post: string };
  summary: string;                // 2-sentence, for large widget
  sun: {
    sunrise: string;              // pre-formatted display string (verbatim)
    sunset: string;               // pre-formatted display string (verbatim)
    srHour: number;               // raw decimal hour for arc math (option b)
    ssHour: number;               // raw decimal hour
    sunPct: number;               // 0–1
    isNight: boolean;
  };
  hourly: Array<{
    h: string;                    // display label 'Now'/'3PM' (not Date-parseable)
    ts: number;                   // epoch ms — machine-readable (PRD 03)
    cond: Condition;
    temp: number;                 // °C
    pop: number;                  // % (0–100)
  }>;                             // next 6
  days: Array<{
    label: string;                // d[0]
    cond: Condition;              // d[1]
    lo: number;                   // d[2]
    hi: number;                   // d[3]  (assert hi >= lo)
    pop: number;                  // d[4], % (0–100)
  }>;                             // next 5
}
```

### US-003: Write the active city's snapshot on every weather commit
**Description:** As a user, I want my widget to match what I last saw in the app for the active city.

**Context — real commit points (no `saveWx` indirection):** `saveWx` has exactly **one** call site, `App.tsx:166`, inside the live-success branch of `loadWeather`. Reference the explicit sites below, not "wherever `saveWx` is called":

1. **Live success** — `App.tsx:164–166`: after `setWx(data)` / `saveWx(c.id, data)`, also write the active snapshot built from `data` (no `staleAt`).
2. **Stale fallback** — `App.tsx:170`: when `loadWeather` catches and falls back to `loadWx`, build the snapshot from `cached.wx` and set `staleAt = cached.ts`.
3. **Batch path does NOT qualify** — `fetchCitiesCurrent` at `App.tsx:201` returns only `CityCurrent { temp, cond, label, humidity }` (`weatherApi.ts:42`). It CANNOT build a full snapshot and MUST NOT be used as a snapshot source. Per-city full data is PRD 06's on-demand fetch.

**Acceptance Criteria:**
- [ ] On the live-success commit (App.tsx:164–166) the active city's snapshot is written.
- [ ] On the stale-fallback commit (App.tsx:170) the snapshot is written with `staleAt = cached.ts`.
- [ ] The active city's snapshot is written to the per-id key `wxai.widget.snapshot.<cityId>` AND to the active-pointer key `wxai.widget.active` (the FULL snapshot, so a provider can read it without knowing the id). See US-005 for the key semantics.
- [ ] The active cityId is also persisted under a small `wxai.widget.activeId` key (bare string) so PRD 06 can map a configured id back to "is this the active one."
- [ ] A `wxai.widget.index` array of `{ id, name, lat, lon }` is maintained from the composite city list `[myLocation.city, ...PRESET_CITIES, ...customCities]` (App.tsx:195–199). For `my-location`, the id string `'my-location'` carries NO coordinates; read `lat`/`lon` from the `City` object instead.
- [ ] Writing is best-effort and never throws into the app's render path (mirror `saveWx`'s swallow-errors behavior; wrap in try/catch).

### US-004: Trigger a widget timeline reload after writes
**Description:** As a user, I want the widget to update soon after I change something in the app.

**Acceptance Criteria:**
- [ ] After a successful snapshot or unit write, the app calls `ExpoSharedDefaults.reloadWidgets()` (→ `WidgetCenter.shared.reloadAllTimelines()`).
- [ ] Reload is debounced/coalesced so rapid successive writes (e.g. a fetch immediately followed by a unit toggle) don't spam reloads.
- [ ] **Verification (testable):** change the active city OR toggle the unit → background the app → within a short window the widget shows the new snapshot. Note `reloadAllTimelines()` is a *budgeted request*, not a guarantee; WidgetKit may coalesce/delay. Do NOT phrase this as "edit weather state" — there is no in-app weather editor.
- [ ] (Optional, debug-only) A hidden debug button forces a snapshot write + reload for deterministic manual testing in the Simulator.

### US-005: Swift decoding model
**Description:** As a widget developer, I want a typed Swift model so the SwiftUI views are clean.

**Acceptance Criteria:**
- [ ] `targets/widgets/Model/WidgetSnapshot.swift` defines `Codable` structs mirroring the schema exactly (field names match JSON keys byte-for-byte, including `tzOffsetMinutes`, `precipProb`, `srHour`/`ssHour`, `ts`).
- [ ] `Condition` is a Swift `enum: String, Codable` with the 8 cases; unknown values decode to a safe default (`cloud`) rather than crashing.
- [ ] `SnapshotStore.loadActive()` reads the FULL snapshot stored under the **`wxai.widget.active` key**; `SnapshotStore.load(cityId:)` reads `wxai.widget.snapshot.<cityId>`. Both JSON-decode from the shared suite and return `nil` on miss/parse failure. (`wxai.widget.active` is a KEY holding a snapshot, not a cityId value — when no cityId is configured, the provider reads the snapshot at this key.)
- [ ] A bundled `placeholder` snapshot constant exists for previews and the "no data" state.
- [ ] Decoding tolerates missing optional fields and a future-greater `schemaVersion` (renders best-effort, never crashes).

## Functional Requirements

- FR-1: The app MUST write the **active city's** full `WidgetSnapshot` to the shared suite on every active-city weather commit (live success at App.tsx:164–166, stale fallback at App.tsx:170). Non-active cities are out of scope here (PRD 06).
- FR-2: The snapshot MUST be JSON-serializable and self-describing via `schemaVersion`.
- FR-3: All temperatures MUST be stored in °C; the `unit` field drives render-time conversion.
- FR-4: The unit MUST be persisted (`wxai.unit`) and mirrored to the shared suite (`wxai.widget.unit`), independent of any weather commit.
- FR-5: The writer MUST be best-effort and MUST NOT throw into the app's UI path.
- FR-6: The Swift decoder MUST never crash on missing/unknown/extra fields.
- FR-7: After writes, the app SHOULD request a widget timeline reload via `ExpoSharedDefaults.reloadWidgets()`, debounced.
- FR-8: The `wxai.widget.index` MUST carry `{ id, name, lat, lon }` for every city in the composite list, kept consistent on add and pruned on removal (FR-9).
- FR-9: Removing a **custom** city (`removeCity`, App.tsx:243) MUST prune its `wxai.widget.snapshot.<cityId>` and its `wxai.widget.index` entry. Presets and `my-location` cannot be removed in-app, so they are never pruned. (If the active-city-only scope means only the active snapshot key exists, cross-reference the per-city prune work to PRD 06 rather than half-implementing it here.)

## Non-Goals (Out of Scope)

- Writing full snapshots for non-active cities (PRD 06 resolves these via on-demand fetch; the batch `fetchCitiesCurrent` data is too thin).
- The widget fetching its own data (PRD 03 adds an independent-fetch fallback; this PRD is app-push only).
- Any SwiftUI rendering (PRD 02+).
- Encrypting the shared container (weather data is non-sensitive; no PII beyond coarse city name and coordinates).
- Cross-device sync.

## Design Considerations

- Keep the snapshot small (well under the few-hundred-KB practical `UserDefaults` comfort zone). Limit `hourly` to 6 and `days` to 5.
- Store a single JSON string per key (one `set(jsonString, forKey:)`) over many primitive keys — easier to version and decode atomically. `wxai.widget.unit` and `wxai.widget.activeId` are the only bare-string exceptions.
- **Snapshot keys (shared contract):** `wxai.widget.active` (full active snapshot), `wxai.widget.snapshot.<cityId>` (per-id), `wxai.widget.index` (array of `{id,name,lat,lon}`), `wxai.widget.unit` (bare `"C"`/`"F"`), `wxai.widget.activeId` (bare cityId). Keep these byte-consistent with PRD 03/06.

## Technical Considerations

- The **custom `ExpoSharedDefaults` Expo module is the default bridge** (US-001). `react-native-userdefaults` is rejected as the default because it lacks `WidgetCenter` reload; it is not a dependency.
- The module must be a local Expo module / config-plugin that survives `expo prebuild` (the generated `ios/` is gitignored, so no native files may be hand-edited inside it).
- The write sites are the live-success and stale-fallback branches of `loadWeather` (App.tsx:164–170), NOT an abstracted `saveWx` wrapper (which has a single call site at :166 and never runs on the stale path).
- The unit mirror is hooked at `onUnitChange` (App.tsx:313), independent of weather commits.
- `WidgetCenter.reloadAllTimelines()` is reachable only from native; `ExpoSharedDefaults.reloadWidgets()` exposes it to JS. It is a budgeted request, not a synchronous guarantee.
- JSON key names in TS (`src/widgets/snapshot.ts`) and Swift (`WidgetSnapshot.swift`) MUST match byte-for-byte. Add a cross-reference comment in both files.

### No-data / empty state (cross-file contract)
- **"Widget added but app never opened":** no `wxai.widget.active` key exists yet (the default Madrid city lives only in JS state; nothing is written to the container until the first commit at App.tsx:164–170). The decoder MUST return `nil` and the widget views (PRD 03/04/05) MUST render an "Open AI Weather to set up" placeholder. State explicitly: **first app launch is a prerequisite for live widget data.**
- **"Configured city removed AND no active snapshot":** if a configured per-id snapshot was pruned and no active snapshot exists, the provider falls back to the placeholder. Define this state's copy in the view PRDs.

## Success Metrics

- 100% of active-city weather commits (live + stale) produce a snapshot write (verify via logging in a debug build).
- The Swift decoder round-trips a real app-written snapshot in an Xcode preview / decode unit test with no data loss (AC-5: TS `buildSnapshot` fixture test + Swift `WidgetSnapshot` decode round-trip test, both asserting `hi >= lo`).
- Corrupt/empty/missing suite → decoder returns `nil`, no crash (verified by a Swift unit test feeding malformed JSON).
- Relaunching the app preserves a selected °F (unit-persistence regression guard).
